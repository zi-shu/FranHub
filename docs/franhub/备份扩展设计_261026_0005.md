## 一、事实基础

### 官方 3.1.1 的落盘结构

| 位置 | 内容 |
|---|---|
| `filesDir/workspaces/<root>/files/` | 工作区文件，Rootfs 内挂在 `/workspace` |
| `filesDir/workspaces/<root>/linux/` | 解包后的 Alpine 根文件系统，带软链接与权限位 |
| `filesDir/workspaces/<root>/tmp/` | 临时目录，可重建 |
| `filesDir/{skills,upload,fonts,media_creation,tool_outputs}` | 现有 FILES 备份项覆盖前四个 |

现有备份 `BackupManager.createBackup(includeDatabase, includeFiles)` 写三类条目：`settings.json`、`database/rikka_hub.db`、`files/<folder>/…`。恢复走 `stageRestore` 暂存，再在 Application 启动、Room 与 Koin 初始化之前由 `PendingRestore.apply` 换入，带 journal 与回滚。

### 参考实现的做法与取舍

布局：`ubuntu/base/rootfs` 单文件 + `ubuntu/volumes/<卷名>/…` + `ubuntu/links.json`，另加 `manifest.json`。清单元数据为 `{version, createdAt, encrypted, entries[{name,size,crc32}]}`。

恢复端四道校验，任一不过就整体中止：version 相等、条目数相等、名字集合相等、每条 size 与 crc32 相等。

取舍一，完整性校验全有或全无。六万余条、1.2 GB 的包，导出中断或文件变动一次，整包拒绝恢复，没有补救余地。

取舍二，没有排除规则。样本包里 `config/npm-global` 占 1205 MB、63422 条，等于把整个 node 全局包目录塞进备份。

取舍三，恢复只换目录不重建。base 与 volumes 换进去以后按 links.json 重建软链接，rootfs 镜像不重新解包，环境状态与镜像容易对不上。

## 三、备份流程

1. 用户勾选「工作区」后，列表显示各工作区名称与占用，逐项勾选。
2. 开始前统计体积，弹窗显示预计包体，用户确认后才写盘。
3. `files/` 与 `linux/` 各打成一个 tar。软链接存 target 字符串，目录优先级、权限位按 POSIX ustar 写，超长路径用 GNU `L`/`K` 扩展。
4. 采集包清单，直接读 `linux/` 里的数据库文件，不启动 proot，不执行命令。
   - Alpine：`linux/lib/apk/db/installed`，取 `P:` 与 `V:` 行。
   - Debian：`linux/var/lib/dpkg/status`，取 `Package:` 与 `Version:`。
   - pip：`linux/**/site-packages/*.dist-info/METADATA`，取 `Name:` 与 `Version:`。
   - npm：`linux/**/node_modules/*/package.json` 的 `name` 与 `version`，只取顶层。
5. 排除规则只作用于 `linux.tar` 与 `files.tar` 内部，写入 manifest 的 `exclusions` 字段，恢复后可见。
   - `tmp/`、`var/cache/`、`var/log/`、`**/__pycache__/`、`.npm/_cacache/`、`.cache/pip/`、`proc/`、`sys/`、`dev/`

## 四、恢复流程

1. 选 zip，先读 `workspaces/manifest.json`，弹窗列出包内工作区，让用户勾选要恢复的项与模式。
2. 模式两种。
   - 全盘替换：该工作区的 `files/` 与 `linux/` 整体换成包内的，旧目录留一份可回滚。
   - 增量合并：逐文件复制，同名覆盖，包内没有的保留。
3. 暂存阶段解 tar 到 `noBackupFilesDir/backup-restore/preparing-*/workspaces/<root>/`，用户此时还能继续用 App。
4. 发布后，下次启动在 Room 与 Koin 之前执行换入。替换模式是目录 rename，一次到位；增量模式是文件复制。
5. 回滚：`originals/` 里的目录换回原位，与现有 `PendingRestore` 的语义一致。
6. `packages.json` 恢复后只在界面列出，不自动重装。

## 六、本版范围

做：工作区文件与 Linux 环境的备份、逐工作区勾选、体积预估、缓存排除、包清单采集、两种恢复模式。

不做，留到后续版本：

- 按包归属逐个文件排除。仅靠 `apk`/`dpkg` 数据库无法区分「基础镜像自带」与「用户后来安装」，一律排除会连 `/bin/sh` 都丢掉，恢复出来的环境不可用。
- 恢复后一键重装包清单。
- WebDAV 与 S3 同步携带工作区，体积可能几百 MB，先只做本地导出导入。
- 备份加密。

## 七、测试计划

单元测试：

- `TarArchive` 往返：普通文件、中文文件名、超过 100 字节的路径、软链接、空目录、可执行权限位、10 MB 大文件。
- 包清单解析：`apk installed` 片段、`dpkg status` 片段、`pip METADATA` 片段、`npm package.json` 片段。

手工验证：

- 真机：建工作区 → 装 python → 备份（勾工作区与 Linux 环境）→ 卸载重装 → 恢复 → 进工作区确认 python 可用、文件还在。
- 增量模式：恢复后确认原有文件未被删除。
- 回滚：恢复中途杀掉进程，重启后确认能续上或回滚。
