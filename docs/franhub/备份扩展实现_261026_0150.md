## 一、这一版做了什么

包名 `zishu.wife.Franhub`，版本名 `v0.1.0`，versionCode 1。

本地导出导入新增两项：

| 项 | 内容 | 包内条目 |
|---|---|---|
| 工作区 | 每个工作区的 `files/` 目录 | `workspaces/<root>/files.tar` |
| Linux 环境 | 每个工作区的 `linux/` 目录（整份 rootfs） | `workspaces/<root>/linux.tar` |

另外写入两份元数据：

- `workspaces/manifest.json`：逐工作区的名称、条目数、字节数、排除规则。
- `packages.json`：apk / dpkg / pip / npm 四类包管理器的名称与版本。

恢复时可选两种模式：全盘替换（旧目录留一份，可回滚）、增量合并（保留包外文件，不回滚）。

## 三、构建环境上踩的四个坑

1. **qemu 包装脚本里的路径失效**。`env/sdk` 里 cmake、ninja、NDK 的 clang 等 x86-64 程序靠 `#!/bin/sh` 包装脚本走 qemu，脚本里写死 `（旧构建环境目录）/...`，迁移后该目录已删。已批量改为 `（本地工作目录）/...`。检测办法：在这些 bin 目录里搜旧工作目录名。`env/bin/wrapped_manifest.txt` 里仍是旧路径，只是清单文档，不影响运行。
2. **依赖拉不下来**。`dl.google.com` 直连超时，缓存里只有 material3 `1.5.0-beta01`，工程要 `beta02`。新增 `env/mirror.init.gradle`，由 `env/build.sh` 通过 `-I` 注入阿里云镜像，不改工程文件。
3. **Git 子模块没内容**。`material3/material-color-utilities` 是子模块，源码 tarball 里是空目录，导致 `dynamiccolor.*` 无法解析。已从 codeload 拉上游 `main` 分支的 `kotlin/` 目录放回原位（43 个 kt，486 KB）。**注意**：取的是上游当时最新，没有锁定提交号。
4. **缺 `google-services.json`**。仓库不带这个文件，Firebase 插件必须要有。已放一份占位配置在 `app/google-services.json`，包名 `zishu.wife.Franhub`，各项编号是假值。**风险**：`Firebase.crashlytics` 与 `Firebase.analytics` 在 `AppModule` 里是 Koin 单例，若初始化失败会启动即崩。真机首次启动要重点确认这一点。

## 五、已知限制

- 按包归属逐个文件排除没做。`apk`/`dpkg` 数据库分不出「基础镜像自带」与「用户后装」，一律排除会连 `/bin/sh` 都丢掉。
- 包清单只记录，不提供一键重装。
- WebDAV 与 S3 不带工作区，避免几百 MB 的同步。
- 恢复的增量模式失败后不能回滚，全盘替换模式可以。
- 只补了中文与英文文案，其余语言显示英文。
